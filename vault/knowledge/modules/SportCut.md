# SportCut (режим «Просмотр»)

Нарезка клипов, плейлисты, анализ. Точка входа UI — `SportCutListView`.

## Ключевые факты (из наработанного опыта)

- **Экспорт**: клипы режутся последовательно (serial), прогресс опрашивается через
  `AVAssetExportSession.progress`, упаковка — streaming zip. Ошибки обязательно
  показывать пользователю, не глотать.
- **Плейлисты / таймлайн**: последовательные таймлайны плейлиста с переопределением
  start/duration на каждое событие, направленный resize, фильтрация рисунков.
- **Разметка в просмотре**: в режиме просмотра показываются рисунки клипов плейлиста
  + скриншоты исходной разметки (два источника данных).
- **Водяной знак клуба**: `ClubLogoWatermarkManager` + редактор настроек; флаг
  `showClubLogo` в `ExportWatermarkOptions`; композитинг в SportCut
  `watermarkVideoComposition`.
- **Фильтры (`SportCutFilterSheet` + `TimelineFilter`)**: внутри категории — «ИЛИ»
  (`isDisjoint`), между категориями (теги / лейблы / события) — «И». Есть поиск по имени
  с массовой отметкой найденного.
- **Лейблы между проектами сшиваются по ИМЕНИ, а не по id.** У каждого проекта своя копия
  коллекции, id разводятся при импорте дублей, у сторонней разметки лейблы синтетические;
  сквозного `primaryID` у `Label` (в отличие от `Tag`) нет. Поэтому фильтр хранит и
  `selectedLabels` (id), и `selectedLabelNames` (нормализованные имена). Любой новый код,
  сопоставляющий лейблы разных `SportCutSource`, обязан учитывать это — иначе фильтр
  выглядит как «И» между проектами.

- **Связь с разметкой — НЕ живая (с 19.08.2026).** `SportCutSource` — это СНИМОК разметки проекта.
  Раньше `SportCutMarkupSyncManager` висел на `.projectTimelinesDidChange` (шлёт
  `InMemoryStorageManager.saveTimelines`) и пересинкивал сессии на каждое изменение разметки —
  идущий счётчик пишет свой штамп раз в секунду, и это давало посекундный рывок на больших
  проектах. Теперь синк только в явных точках: вход в сессию просмотра
  (`syncAllProjectSources`), вход в проект разметки (`WindowsManager.openVideo`), выход из него
  (`closeAll`, после финализации счётчиков), кнопка «Обновить разметку в режиме просмотра» в
  `FullControlView` и открытие окна просмотра из разметки. Обновляются ТОЛЬКО `timelines` и снимок
  пула тегов/лейблов; синк обязан пропускать no-op и не гонять `SportCutClipCache.autoCacheIfNeeded`
  (`updateSession(_:runClipCache:)`). Данные при этом не теряются: клипы плейлистов самодостаточны
  (рисунки, комментарии, счётчики лежат в самом событии).
- **Клип плейлиста — самостоятельный объект.** С момента добавления он живёт отдельно от
  разметки: правки/удаление исходного штампа его не касаются, границы меняет только пользователь
  (`eventStartOverrides` / `eventDurationOverrides`). Поэтому `SportCutSession.timelineResolvedEvent`
  теперь ПРОПУСКАЕТ событие как есть (раньше пересобирал из текущих таймлайнов — после появления
  непрерывной синхронизации это уводило бы уже нарезанные клипы под пользователем). Метод оставлен
  единой точкой всех путей воспроизведения/экспорта: правило описано в нём одном.
- **Клипы живого проекта**: у него нет файла, поэтому `SportCutPlayerManager.liveAsset(for:)`
  играет склейку уже закрытых сегментов лайва (как пересмотр). Признак живого источника —
  ПУСТАЯ `videoBookmark`. Склейка наращивается добавлением новых сегментов (полная пересборка на
  каждую ротацию — сотни ассетов на главном потоке), плееру отдаётся `copy()`. Ротацию сегментов
  на время просмотра включает панель разметки (`startReviewRefresher`).
- **Лайв в просмотре**: проект, который пишется, добавляется `addLiveProjectSource` с ПУСТОЙ
  закладкой (файла ещё нет). Таймлайн считает длительность как `max(видео, конец последнего
  штампа)`, поэтому источник растёт по разметке; плеер на нерезолвящийся URL просто пропускает
  событие. На финализации `WindowsManager.rebindViewingSources` → `rebindProjectSources`
  переводит источник на импортированный проект (у новой записи МЕНЯЕТСЯ id проекта) с файлом и
  финальной разметкой; при дозаписи id тот же, но обновляются закладка и разметка.

## Экспорт: пустые дорожки роняют AVAssetExportSession
- Композиции экспорта заводят аудио-дорожку ДО разбора исходников. Если звука нет ни у одного
  куска (запись экрана, немой mov), дорожка остаётся без сегментов, и экспорт падает с
  «Operation Stopped» (`AVFoundationErrorDomain -11838`, внутри `OSStatus -16976`) — по тексту
  ошибки причину не угадать. Перед созданием сессии экспорта обязателен
  `composition.removeEmptyTracks()` (см. `ExportDiagnosticsLog.swift`).
- Разбирать любые отказы экспорта — по файлу `exportDiagnostics.log`
  (`…/Application Support/YouChip-Stat/`), а не по коду: там сегменты, дорожки, preset,
  инструкции видео-композиции и цепочка `NSUnderlyingError`.
- `SportCutSessions_v1` лежит в UserDefaults и уже перевалил за лимит CFPreferences (4 МБ):
  при каждом изменении сессии переписывается весь блоб (у пользователя ~27 МБ). Учитывать при
  добавлении новых полей в сессию.

## Счётчики (секундомеры/таймеры) в просмотре
- Записи счётчиков приезжают в сессию вместе с остальными дорожками (`SportCutSource.timelines`,
  дорожки узнаются по `TimelineLine.clockId` / легаси-id) — читать их только через
  `[TimelineLine].clockStamps`.
- На кадре их показывает `SportCutClockOverlayView` поверх плеера просмотра и панели клипов
  плейлиста в окне разметки. Данные — `SportCutPlayerManager.currentClockOverlayItems()`:
  пересечение записи с ТЕКУЩЕЙ позицией на абсолютной шкале исходника
  (`absoluteVideoTimelineTime`), поэтому режим (клип / последовательный плейлист / единый фильм)
  и ресайз клипа значения не имеют — пересчитывать записи не нужно. Рисует общая
  `ClockOverlayCanvas` (та же, что в разметке): перетаскивание и размер общие с разметкой.
- Экспорт: тумблер «со счётчиками» в `SportCutExportSheet` (`ExportWatermarkOptions.showClocks`),
  слои добавляет `ClockExportOverlayBuilder.addLayers` в `watermarkVideoComposition`; placements
  считаются по каждому сегменту от диапазона события в исходнике. Видео-композиция строится и
  без вотермарки, если включены счётчики.
- **Клип несёт счётчики с собой.** `SportCutEvent.clockRecords: [ClockRecordSnapshot]?` — копия
  записей (показания + границы в исходнике + флаг Primary Counter момента), снимается в
  `SportCutEvent.from(stamp:line:source:)` и обновляется на каждом `updateSession`
  (`SportCutSessionManager.refreshedClockSnapshots`), пока разметка источника жива. И оверлей, и
  экспорт идут через `SportCutClockSnapshotBuilder.resolvedRecords(for:source:)`: свежие записи
  источника, а если их не стало (проект/разметку снесли) — снимок клипа. Правило «клип работает
  всегда и со всем» распространяется и на таймеры.
