## 2026-08-19 — Счётчики: Primary Counter = только тега МОМЕНТА (просмотр + экспорт)
- **Задача:** в просмотре момента/клипа на кадр лезли ВСЕ счётчики, а не «с флагом Показывать
  на видео + Primary Counter тега этого момента». Тот же баг в экспорте: фильм наносил все
  счётчики, а клипы — вообще ничего.
- **Причина:** `primarySet` собирался из Primary Counter'ов ВСЕХ тегов, чьи штампы пересекали
  плейхед/окно (в командных видах перекрытий много → «все»). Правильный образец —
  `MomentViewerView` (дабл-клик): берёт Primary только штампа самого момента.
- **Как правил:** `ClockExportOverlayBuilder.placements` больше не собирает primary сам —
  принимает `momentPrimaryClockIds` от вызывающего; фильтр остался `showOnVideo || primary`.
  Хелпер `ClockExportOverlayBuilder.momentPrimaryClockIds(for: TimelineStamp?)`
  (`stamp.primaryClockId ?? findTagById`). Прокинул момент во все места:
  `ExportHelper` (фильм ×2 + клип — `segment.stamp`), `OrganizerView` (×3 — `resolvedStamp`),
  `SportCutExportSheet` (клип + фильм ×2 — новый `momentPrimaryClockIds(for:event,session:)`
  ищет штамп события по `stampID` в дорожках источника), а также оверлей просмотра
  `SportCutPlayerManager.currentClockOverlayItems` (Primary только `currentEvent`). Живой оверлей
  разметки `ClockVideoOverlayView` не трогал — там нет одного «момента».
  См. [[project_clock_objects]].

- **Задача:** записи счётчиков переносятся в режим просмотра, но нигде не показывались. Нужно:

  убрать ВЫБОР записей: наносится всё, что видно на кадре в этот момент. Исключение — пересмотр
  момента по двойному клику (`MomentViewerView`), там панель с галочками остаётся.
- **Сделано:**
  - Отрисовка вынесена из `ClockVideoOverlayView` в общую `ClockOverlayCanvas` (+ тип

    записи), `watermarkVideoComposition` принимает `clockPlacements` и добавляет слои через
    существующий `ClockExportOverlayBuilder.addLayers`; placements считаются по каждому сегменту в
    `exportAsClips` / `exportAsFilmBuild` / `exportAsFilmPerPlaylistBuild`. Видео-композиция теперь
    строится и когда вотермарка выключена, но счётчики включены.
  - Выбор записей убран: `ExportWatermarkOptions.clockStampIDs` → `showClocks: Bool`,
    `ClockExportOverlayBuilder.placements(enabled:…)` наносит все пересечения,
    `ExportModeSelectionSheet` — один тумблер вместо списка галочек.
  - Экспорт теперь повторяет ЭКРАН и по месту: `addLayers` берёт позицию/масштаб из

    двигали — прежняя стопка в правом верхнем углу.

## 2026-08-19 — Редактор в лайве: кадр и время — по ОКНУ, из которого открыли
- **Баг (по фидбеку):** при включённой «Разметке пересмотра» кнопка «Редактор» в окне разметки
  (лайв) открывала редактор с кадром ПЕРЕСМОТРА, и метка рисунка вставала в точку пересмотра,
  а не туда, где стоял живой плейхед.
- **Причина:** `VideoPlayerViewModel.performTakeScreenshotForEditor` (это действие шлёт только
  кнопка «Редактор» окна разметки, `VideoPlayerView`) первым делом проверял `isReviewMode` и
  уходил в `openEditorFromReviewPlayer`. Так как пересмотр бывает только в лайве, live-ветка
  ниже была фактически недостижима, пока открыт пересмотр.
- **Сделано:** в `performTakeScreenshotForEditor` порядок перевёрнут — в лайве всегда
  `openEditorFromLiveFrame` (живой кадр + `editorScreenshotVideoTime = currentTime`, т.е. время
  ЛАЙВА). Кадр/время пересмотра остались за собственным входом окна пересмотра —
  `.takeReviewScreenshotForEditor` → `openEditorFromReviewPlayer` (`reviewCurrentTime`).
  Правило: источник кадра определяет ОКНО, из которого открыли редактор, а не активный плейхед
  разметки.

## 2026-08-19 — Бирюзовый плейхед пересмотра: полный функционал + превью интервала по нему
- **Баги (по фидбеку):** (1) у второго плейхеда не было «головы»-треугольника в закреплённом баре
  таймлайнов — только стебель на дорожках; (2) его нельзя было тянуть мышью, как основной;
  (3) при «Разметке пересмотра» растущий интервальный штамп рос за БЕЛЫМ (лайв) плейхедом, хотя
  готовый штамп ложился правильно. Требование: второй плейхед = 100 % функционала основного.
- **Сделано:**
  - `MarkupClock` (в `PlaybackClock.swift`) — часы ВРЕМЕНИ РАЗМЕТКИ (`markupTime`): лайв или
    пересмотр, по режиму. Пишутся из `VideoPlayerManager` (`didSet` у `currentTime`,
    `reviewCurrentTime`, `markupUsesReviewTime`). `IntervalRecordingBars` переведён с
    `PlaybackClock` на `MarkupClock` — растущий штамп идёт за тем плейхедом, по которому пишут;
    «пишущий» край штампа красится в цвет этого плейхеда (белый/бирюзовый).
  - `ReviewPlayheadView` из индикатора стал полноценным плейхедом: свой
    `PlayheadEdgeScrollController` (`reviewPlayheadDragController` в `FullControlView`), drag с
    edge-scroll'ом, превью-seek видео пересмотра ~30 Гц, пауза на время перетаскивания и
    возобновление после. Механика вынесена в `enum ReviewPlayheadDrag` — общая со «головой».
  - `PinnedTimelineRulerView`: бирюзовая «голова»-треугольник + своя зона захвата в закреплённом
    баре (zIndex выше основной, когда включена «Разметка пересмотра»). Клик по линейке в
    пересмотре ведёт плейхед ПЕРЕСМОТРА (`seekReview`) — основной в лайве всё равно прибит к краю.
  - `VideoPlayerManager`: `seekReview(to:resumePlaybackAfterSeek:)` (клампит по `reviewDuration`,
    сразу проставляет позицию), `seekReviewForTimelineScrubPreview(to:)`, `reviewDuration`,
    `reviewSeekSuppressUntil` — 10-герцовый observer пересмотра не откатывает позицию во время
    нашего seek'а (иначе плейхед дёргался назад при перетаскивании).
  - Цвет бирюзового плейхеда вынесен в глобальную `reviewPlayheadTint` (стебель, голова, край
    растущего штампа берут её же).

## 2026-08-19 — КРИТ: потеря просмотра/разметок с таймерами (падение декодера StampClockInfo)
- **Симптом:** «слетели все проекты просмотра и часть разметок, где были таймеры».
- **Причина:** в `StampClockInfo` (СИНТЕЗИРОВАННЫЙ Codable) добавил `var showOnVideo: Bool = false`.
  Синтезированный `Decodable` НЕ использует дефолты — для необязательного поля зовёт `decode` и
  падает `keyNotFound` на СТАРЫХ записях без ключа. Ошибка каскадит: битый clockInfo → битый
  `TimelineStamp` → падает весь `[TimelineLine]`/`[SportCutSession]`. Сессии — один блоб в
  UserDefaults (`SportCutSessions_v1`), одна битая сессия роняла ВЕСЬ массив → `sessions=[]`, и
  следующий `saveSessions` мог перезаписать блоб пустотой. (Точно как TASK-008 с `isInterval`.)
- **Исправлено:**
  - `StampClockInfo`: свой Codable в РАСШИРЕНИИ (мембервайз-init сохранён) с `decodeIfPresent`
    для `showOnVideo`/`keyframes` и мягкими дефолтами прочих полей.
  - `SportCutSessionManager.loadSessions`: фолбэк на построчный разбор (`FailableDecodable`) — одна
    битая сессия не роняет все; при полном провале НЕ обнуляем (не перезаписываем блоб пустотой).
  - `InMemoryStorageManager`: `decodeTimelinesLenient` (целиком → построчно `FailableLine`) в
    `loadTimelines` и `loadTimelinesFromFile` — битая строка пропускается, проект не теряется.
- **Восстановление:** данные на диске целы, если не были перезаписаны пустотой после правок.
  Разметки — `~/Documents/YouChip-Stat/Timelines/<id>.json`; сессии — UserDefaults; бэкап —
  `~/Library/Application Support/YouChip-Stat-Backup/`.

- **Итог:** пауза счётчика деактивирует интервальный тег через stateSync (и наоборот — стоп тега

## 2026-08-19 — Счётчики привязаны ко ВРЕМЕНИ ВИДЕО + своя пауза (заморозка)
- **Задача:** таймер/секундомер должен идти по ВРЕМЕНИ ВИДЕО (как интервальный тег), а не по

- **Сделано (переписан `ClockRuntimeManager`):** 3 состояния — простаивает (recording=false,

  штамп попал в снимок таймлайнов при финализации лайва). Круг таймера (.restart) — отдельный

- **Финализация при конце лайва:** `stopLiveSessionAndSwitchToMarkupMode` теперь зовёт

  дописываются на таймлайн (как просил). Также на выходе из проекта (`closeAll`) и ⌘Q
  (`finalizeLiveSessionForQuit`).
- **Связки (`KeyBindingRuntimeManager`):** `onStopClock` → `onPauseClock` (деактивация счётчика =
  его пауза); новый колбэк `isClockRunning`. `handleClockTap`: idle→пуск(+цепочка), идёт→пауза,
  пауза→снять. `intervalInversion` clock: идёт→пауза иначе пуск. Эксклюзив/stateSync-выключение

## 2026-08-18 — stateSync: зеркалить по факту смены состояния (интервал↔счётчик, любые триггеры)
- **Задача/баг:** stateSync между интервальным тегом и таймером/секундомером не срабатывал —
  при активации интервала счётчик не стартовал (только по прямому клику по счётчику). Нужно, чтобы
  синхронизация шла при ЛЮБОЙ смене состояния: прямой тап, связки активации/деактивации/инверсии,
  эксклюзив, достижение нуля таймером — «состояние-то меняется». Связка двунаправленная.
- **Причина:** первая реализация цепляла stateSync к точкам НАЖАТИЯ (`handleButtonTap` /
  `handleClockTap`), а не к фактической смене состояния. Старт интервала из другой связки
  (`onStartIntervalTag`) и старт/стоп счётчика из связок/по нулю мимо этих точек не отражались.
- **Сделано (переход на choke-points):**
  - `KeyBindingRuntimeManager.notifyStateChanged(kind:elementId:activated:)` — ЕДИНАЯ точка
    зеркалирования, с re-entrancy-гардом (`stateSyncInProgress` + инстанс-`stateSyncVisited`), чтобы
    старт/стоп, вызванные самой синхронизацией, не запускали новый каскад. Прежние
    `applyStateSyncActivation/Deactivation` и их вызовы из handleButtonTap/handleClockTap/isStopping
    удалены; `applyBinding` `.stateSync` — no-op.
  - Интервальные теги: `notifyStateChanged` зовётся из ЕДИНСТВЕННЫХ choke-точек смены состояния —
    `startIntervalRecording` (после append, activated:true) и `finishIntervalRecording` (после
    remove, activated:false) в `TagLibraryView`. Покрывает и прямой тап, и запуск из связок.
  - Счётчики: `ClockRuntimeManager.onStateChanged(id,isActive)` шлётся в конце `start()`/`stop()`
    (значит — тап, связки, достижение нуля). Подавляется на `pauseAll` (`suppressStateChanged`),
    чтобы заморозка при выходе/редакторе не завершала связанные интервалы. Колбэк подключён в
    `TagLibraryView.wireRuntimeCallbacks` → `notifyStateChanged(kind:.clock…)`.
- **Итог:** старт/стоп интервала зеркалит счётчик и наоборот, каким бы путём состояние ни менялось.

    разметки (остановка записи → склейка → импорт проекта с разметкой), а `reply(true)` идёт

    `finalizeLiveSession` получил completion и защиту от повторного входа
    (`isFinalizingLiveSession`), у live-окон снимаются делегаты, чтобы их закрытие при выходе
    не запустило финализацию второй раз.
- **Потери при обрыве:** максимум последние 30 с, обычно меньше (подхватывается хвост).
  Резервное копирование теперь страхует только настоящие аварии — штатный выход сохраняет всё.

## 2026-08-03 — Краш при старте записи интервального тега (регрессия TASK-001)
- **Задача:** приложение падало при включении записи интервального тега. В логе —
  `NSGenericException: window ... more Update Constraints in Window passes than there are views`
  на `NSPanel 153×50` (+ отдельные предупреждения CFPrefs о записи ≥4MB в UserDefaults).
- **Что сделано:** краш устранён. Причина — `ClipSaveToastPresenter` (тост из TASK-001):
  `NSHostingView` внутри `NSPanel` сам управлял размером окна через
  `updateWindowContentSizeExtrema`, осцилляция размера → бесконечный цикл updateConstraints.
  BUILD зелёный. Отдельно зафлажен баг >4MB в UserDefaults (потеря данных) — вынесен отдельно.
- **Как правилось:** `ClipSaveToastPresenter.present()` — `hosting.sizingOptions = []`
  (macOS 13+) + hosting кладётся в контейнер-`NSView`, а не в `contentView` панели напрямую
  (фикс для macOS 12) → hosting больше не управляет размером окна.
